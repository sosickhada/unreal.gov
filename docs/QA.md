## 실제 브라우저 검증

후속 Chromium 수정으로 실제 4장/5장 PNG 총 9개를 생성했고, 1080×1350·실제 폰트·텍스트 경계·고정 엔딩 픽셀 일치 및 호스트 진단용 Chromium 잔존 없음 검증이 통과했습니다. 5장은 렌더/종료 57.739초 및 smoke 전체 PASS입니다. 4장은 렌더/종료 67.945초였고 후속 파일 비교 도중 75초 제한을 넘겨, 별도의 저장 이미지 검증으로 PASS를 확인했습니다. 성능 편차는 남아 있습니다.

자세한 원인, 제한, 실행 명령과 증거는 [렌더링 보고서](RENDERING.md)를 확인하세요. 산출물은 `output/render-smoke/acceptance/verification.json`과 같은 디렉터리의 PNG입니다. 긴 제목의 실제 overflow 거절도 통과했습니다. 렌더링 코드 검증은 완료했지만 서비스 전환·실전 API/게시 검증 완료를 의미하지 않습니다.

## 아직 통과하지 않은 운영 인수 조건

1. 실제 VM의 systemd 활성 상태·시간 동기화와 디렉터리 권한 확인.
2. 로컬 실제 4장/5장·overflow 검증은 통과. 서비스 사용자·리소스 제한 하에서 성능과 디자인 최종 인수 확인 필요.
3. 승인된 최소 RSS·Claude 응답과 Telegram 후보→선택→수정→심의 실전 검증.
4. 실제 Caddy 공개 HTTPS JPEG를 VM 외부와 Meta에서 내려받을 수 있는지 확인.
5. Pixabay 실제 반환 이미지·라이선스·얼굴 노출 수동 검수 절차 검증.
6. Meta 앱/토큰/권한/연결 계정·Graph 버전과 API 필드 호환 확인. 게시 전 sandbox/역할 계정에서 검증.
7. 별도 승인된 게시물 1건 게시 및 재실행 중복 차단. 타임아웃은 강제 재게시하지 않고 공식 API로 조정.
8. 백업 복원 연습, worker 강제 종료 후 running/uncertain 복구, Telegram 전달 유실 확인 후 재전송.
9. GitHub 기존 예약 비활성화 확인 후 timer 활성화. VM self-hosted runner 수동 접수의 동일 DB 사용 확인.

## 남은 제한

- 사실 검증·한국어 문장 품질·라이선스 적용·초상권·실사성·관련성은 사람의 최종 검토가 필요합니다.
- 얼굴 태그 필터는 시각적 얼굴 검출기가 아닙니다. 자동 얼굴 없음 보장은 하지 않습니다.
- 외부 서비스의 exactly-once는 보장하지 않습니다. 불확실한 유료/게시 요청은 자동 중단하며, 공식 서비스 확인 후 승인된 수동 DB 조정이 필요합니다. 자동 조정 도구는 아직 없습니다.
- 자동 재시도 대신 명시적 운영자 재개를 선택했습니다. API 장애 때 자동으로 완주하는 고가용성 시스템은 아닙니다.
- 기본 주제 사진 정책은 수동 검토 등록 전 대기합니다. 무인 이미지 자동 승인 기능은 제공하지 않습니다.
- Facebook Login + Page 연결 방식만 구현했습니다. Instagram Login의 별도 토큰/권한 체계는 지원하지 않습니다.
- 기존 승인 데이터는 보존하지만 새 검토·승인을 소급하지 않습니다. 출처 없는 과거 초안의 자동 이관은 구현하지 않았습니다.
- 독립 모니터링·원격 백업·인증 자동 갱신은 운영 인프라 설정 과제입니다.
