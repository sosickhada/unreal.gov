# 비현실문제부 창작 엔진 2.0

이 변경은 역할별 프롬프트 교체에 더해 다단계 작업 실행, 저장된 요청의 재사용,
독립 심사, 제한된 재작성, 보류, 5장 서사 렌더링, Telegram 수정과 재심 접수를 구현한다.
실제 유료 모델의 재미·한국어·판정 의외성 향상은 이번 오프라인 검증으로 입증하지 않는다.

## 브랜드와 역할

사건은 지나치게 현실적이고 해결 방식은 지나치게 비현실적이어야 한다.
공감과 의외성이 핵심이며, 모든 원고에 감정 5단계를 강제하지 않는다. 생활 훈계,
법률 상담, 실제 기관 사칭, 개인 특정, 말장난과 면책으로 끝나는 결말은 지양한다.

프롬프트 전문은 `bureau/prompts/v2/`의 brand/ideas/conflict/verdict/draft/editor/image_brief.txt에 있다.
brand와 역할 파일은 실제 API의 system에, 동결된 장면·이력·수정 요청은 user JSON에 분리한다.
프롬프트 버전은 `creative-2.0.0:<stage>`이며 실제 요청 SHA-256으로 파일 내용 변화도 검출한다.

## 실제 실행 경로

1. 최소 12개 구체적 사건을 6개 이상 영역에서 탐사한다. 예시 소재를 재사용하지 않는다.
2. 로컬 행동·앵커·중복·영역 검사를 거쳐 Telegram에 3개 선택지를 보낸다.
3. 사용자가 선택한 소재의 A/B 행동·주장·쟁점을 동결한다. 소재 단계에 판정은 없다.
4. 선택 소재마다 서로 다른 판정 유형 3~5개를 생성한다. anchor와 조치·논리·부작용 및
   기준 2개 이상을 요구한다. 높은 적합성 없이 다양성만으로 약한 판정을 고르지 않는다.
5. 선택한 판정과 포맷에 맞춰 5장 원고를 작성한다.
6. 별도 system/새 대화의 편집장이 10개 기준과 실제 문장 인용·이탈 장면·갈등/판정/결말
   개선안을 제출한다. 작가의 판정 자기점수는 편집장에게 전달하지 않는다.
7. 모두 3점 이상·합계 38/50 이상, 사실 일관성·인물 비특정·판정 인과관계·실제 원고 인용이
   맞을 때만 원고 승인으로 보낸다. 점수는 재미의 객관적 증명이 아니다.
8. 미통과 시 관점/판정/부작용 변경을 허용해 최대 2회 재작성한다. 여전히 미통과하면
   `editorial_hold`와 '게시 보류' 보고로 끝내며 렌더·게시 작업을 만들지 않는다.
9. 사용자의 원고 승인 후에만 이미지 brief → 기존 검색/선택/OWN 업로드 → 렌더가 진행된다.
10. 이미지 앨범 전송 성공 후 실제 계정·원고·자산에 결합된 별도 공개 게시 승인을 보낸다.

구형 4개 원본 슬라이드는 그대로 렌더링한다. 새 schema_version=2는 아래 역할 5개를
각각 독립 페이지로 렌더링하며 고정 엔딩 이미지를 삽입하지 않는다.

| 포맷 ID | 실제 페이지 역할 |
|---|---|
| hearing | 접수 → 경위 → 주장 → 판정 → 후폭풍 |
| emergency | 상황 → 즉시 명령 → 적용 범위 → 예외 → 부작용 |
| reply | 민원 → 배경 → 회신 → 집행 → 이후 변화 |
| reversal | 최초 판정 → 이미 있던 증거 → 반론 → 번복 → 결과 |
| decree | 관행 → 정의 → 규칙 → 빈틈 → 부작용 |
| appeal | 기존 판정 → 실제 반론 → 재검토 → 재심 결정 → 결과 |

상황을 판정에 맞춰 사후 변경하지 못하도록 facts 해시와 원문 동등성, 장면 fact_refs,
판정 anchor를 검사한다. 자연어 속 모든 허구 추가/모순을 로컬 코드만으로 완전 탐지하지는
못하므로 독립 심사와 사용자 최종 검토를 함께 유지한다.

## 판정 라이브러리

A 발언 그대로 집행 / B 책임 역전 / C 감정·시간·눈치 계량화 / D 행동 제도화 /
E 갈등에 맞는 대칭 의무 / F 해결하며 문제 발생 / G 예외가 규칙 무력화 /
H 사물·상황에 책임 / I 과도한 증거 / J 관행 금지·의무화.

후보별 적합성·의외성·유머 점수는 설계 참고값이다. 최근 포맷+판정 패턴을 피하되
적합성 기준을 못 넘으면 억지로 다른 유형을 택하지 않고 보류한다. 다양성은 품질 동점의
최종 후보 사이에서만 작용한다. 최고 적합성 판정이 최근 패턴과 겹치면 낮은 품질의
유형으로 갈아타지 않고 새 설계를 요청하는 보류로 처리한다. 기존 원고의 판정
발췌도 편집장 문맥으로 전달한다. 로컬 중복 검사는 문자열/행동 식별자 기반이며
신경망 의미 검색 또는 절대적인 독창성 보증이 아니다.

## 모델·원장·비용

`CONTENT_ENGINE_VERSION=2`로 운영 경로를 선택한다. 미설정은 구형 호환 경로다.
각 모델 설정이 비어 있으면 현재 CLAUDE_MODEL(운영 Haiku)을 상속한다.

| 단계 | 환경변수 | 상위 모델 |
|---|---|---|
| 소재 | CLAUDE_IDEA_MODEL | 금지, Haiku 계열 |
| 갈등 | CLAUDE_CONFLICT_MODEL | 금지, Haiku 계열 |
| 판정 설계 | CLAUDE_VERDICT_MODEL | 금지, Haiku 계열 |
| 최종 원고/재작성 | CLAUDE_DRAFT_MODEL | 선택 가능 |
| 독립 편집장 | CLAUDE_EDITOR_MODEL | 선택 가능 |
| 승인 후 이미지 brief | CLAUDE_IMAGE_MODEL | 금지, Haiku 계열 |

`creative_calls`는 요청 전 모델 ID·역할·프롬프트 버전·요청 해시·system/user JSON을 저장한다.
응답은 기존 checkpoints에 보존하고 입력/출력 토큰과 선택적 비용 추정을 저장한다.
요청이 달라진 상태로 같은 체크포인트를 재호출하지 않는다. 새 모델/프롬프트의 재생성은
명시적인 새 revision에서 수행한다. uncertain 응답은 자동 재시도하지 않는다.

`CLAUDE_<STAGE>_INPUT_PER_MTOK_USD`와 OUTPUT 값을 검증된 단가로 지정할 수 있다.
미설정 비용은 null=미확인이다. 0원이나 무료라고 표시하지 않는다. 실제 청구액은 아니다.
일일 기존 12회/예약 360,000토큰 상한을 유지한다. 금액 기준의 계정 전체 청구 상한이 아니다.

편당 정상 원고 핵심은 갈등·판정·작성·편집장 4회다. 최악의 내부 재작성은 4회 추가다.
일일 소재 1회와 원고 승인 후 brief 1회를 합치면 첫 시도 약 6회, 최대 약 10회다.
재심·새 사용자 수정은 별도 요청이며 일일 상한 안에서만 수행한다.

예산 예시(최신 가격 검증 아님): 모든 호출을 입력 2,000/출력 2,000토큰으로 단순 가정하고
저장된 Haiku 단가 $0.10/$0.50 per MTok를 적용하면 6회 $0.0072, 10회 $0.012다.
입력/출력 크기가 단계마다 달라 실제 견적은 달라진다. 원고+편집장에 가정 단가 $3/$15를
쓰면 두 호출 1라운드는 $0.072, 3라운드는 $0.216이며 나머지 Haiku·이미지·세금은 별도다.
1달러=1,800원이라는 로컬 예산 환산을 쓰면 각각 약 130원/389원이다. 현재 모델 요금의
검증 결과로 해석하지 않는다. 이번 유료 모델 호출은 0회다.

## Telegram과 게시 보호

- `/editor ID`, 편집장 의견 버튼: 인용 문장·점수·이탈 장면·구체적인 편집 의견 조회.
- 보류 화면의 새 버전 요청: 사용자가 방향을 입력하면 기존 revision/CAS/멱등성으로 재작성.
- 공식 최종 화면: 원고·판정 수정, 이미지 수정, 편집장 의견과 기존 승인/취소 제공.
- `/appeal PUBLISHED_ID 반론`: 허용된 사용자의 실제 반론을 published 원본에 연결한다.
  v2 갈등 brief가 없는 구형 게시물은 자동으로 사실을 만들어 재심하지 않고 거절한다.
  새 선택/원고/공개 승인을 만들며 원본 게시물을 수정하지 않는다.
- 일반 거절 피드백을 실제 재심 반론으로 둔갑시키지 않는다. source_ref가 일치하는 실제
  사용자 반론만 appeal의 근거로 허용한다. 테스트 반론은 테스트 DB에서만 사용한다.
- 원고/이미지 변경은 기존 Instagram 승인 레코드를 해제한다. 최종 게시 직전에도
  fingerprint, 독립 편집장 원문 해시·심사 기록, 로컬 이미지 해시를 다시 검사한다.
- 테스트 전용 데이터는 실제 이미지 준비와 공개 게시에서 차단한다.
- 기존 공개 게시 ID/URL 저장·중복 방지·불확실한 외부 쓰기 보호를 유지한다.

## 검증 재현

```bash
.venv/bin/python -m bureau.cli creative-compare --output output/creative-v2
.venv/bin/python -m bureau.cli creative-usage
.venv/bin/python -m unittest discover -s tests
.venv/bin/python -m unittest discover -s tests -p test_creative_v2.py
```

`tests/fixtures/creative_v2_cases.json`은 기존 Claude 원고 3건 + 신규 가상 소재 5건의
수기 개선 예시다. 모든 신규 사례와 개선 원고를 test_only로 표시한다. 실제 모델을
호출하거나 모델 점수 상승을 성공 증거로 삼지 않는다. 비교 산출물에는 기존/개선 원고,
3개 판정 방향, 후폭풍, 기관 논리, 반복 표현 횟수, 독자 참여 쟁점과 사람 검토 항목을 담는다.

오프라인 이미지 결과는 output/creative-v2-render/에 있으며 공개 서버에 노출하지 않는다.
'오프라인 테스트 · 게시 금지' 표시는 본문과 분리된 고정 영역에 표시한다.

## 운영 적용과 다음 실제 시험

운영 DB를 삭제/초기화하지 않고 백업 후 schema 7 테이블을 추가한다. 구형 본문,
게시 ID/URL, 승인 기록과 불확실한 요청을 보존한다.

이번에는 `PAID_AI_CALLS_ENABLED=0`으로 유료 AI를 보류하고 engine=2를 설치한다.
Claude 및 유료 이미지 어댑터는 이 보류를 호출 전에 확인한다. Worker의 기존 승인 게시와
outbox 처리는 유지한다. 이 플래그는 독립 실행되는 임의 외부 스크립트/계정 전체의
청구를 통제하는 보안 경계는 아니다.

다음 실제 시험은 사용자의 별도 유료 호출 승인, 실제 계정의 모델 접근·최신 가격 확인,
하루 6~10회 범위의 예산 확인 후 진행한다. 먼저 Haiku 기준 1편을 독립 편집장과 함께
생성하고 수기 사례와 맹검 비교한다. 게시 성공과 재미 향상을 같은 지표로 보고하지 않는다.
최종 공개 게시에는 이번에도 해당 콘텐츠에 대한 별도 Telegram 승인이 필요하다.
